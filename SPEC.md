## 1.0 in one sentence

I play Uncharted 1, 2 and 3 from my own dump of the PS4 collection on my AMD handheld and my Strix Halo tablet (SteamOS, from Game Mode) and my RTX 3090 Ti desktop (Windows), each game plays start to finish on the AMD handheld, and the same save loads on those three devices, my Mac and my iPhone or iPad through save-relay. The Mac and the iPad also play with a controller (owner rulings, 2026-11-17). On each of these devices the game plays with an Xbox, PlayStation, Switch or other controller and shows that controller's buttons, and save-relay is built in and set up from the launcher (on the iPhone or iPad, from the app) (owner rulings, 2026-11-18).

## A fork, built our way

This repo is a fork of [Supermedo/uncharted_pc](https://github.com/Supermedo/uncharted_pc) (upstream plan: its [README](https://github.com/Supermedo/uncharted_pc/blob/main/README.md) and [docs/ROADMAP.md](https://github.com/Supermedo/uncharted_pc/blob/main/docs/ROADMAP.md)), carrying the spacepepperoni Linux fork. Our delta (R18) is now most of the project:

| Delta | Upstream? |
|---|---|
| Our code in Rust: launcher, prep tools and the host runtime (`src/`); shadPS4 (`gpu/`) stays C++ | keep on our fork |
| Continue screen launcher (Rust + Slint), home build hubs, fleet view, Steam artwork | keep on our fork |
| Android, Mac, iPhone/iPad builds | keep on our fork |
| Shared saves through save-relay | keep on our fork |
| Linux build, SteamOS packaging, handheld profiles (20 W, 30/60 Hz) | keep on our fork |
| Correctness fixes (compute fences, small copies, the review's play-breaking bugs) | send upstream as bug reports (code PRs need my word) |

Upstream syncs (R21) keep coming for `gpu/`, assets and patches. Once a module of ours is Rust, upstream's C or Python change to it becomes an `upstream-sync` issue that ports the change by hand.

## Problem

I want to pick up any of my devices and keep playing the collection, but today the port runs well only on Linux PCs, its launcher is Python and Tk, every device prepares its own copy from the dump, and saves stay where they were made.

## Solution

One Rust engine with a Slint launcher on every device, opening on the Continue screen. Two home build hubs hold the dump and prepare each device's install, and since the owner's rulings of 2026-11-17 the Mac is a third at 1.0, for the Mac and the iPhone or iPad; the other devices pull it over the home network. save-relay wraps every start. The host runtime moves from C to Rust module by module, so the game keeps building and booting at every step. Android adopts the FEXCore route, Apple the recompiler and Metal route; shadPS4 stays the renderer.

## User stories

1. As the owner, I want to pick up any of my devices and continue the same save, so that I never copy saves by hand.
2. As the owner, I want to start each game from Game Mode on my handhelds, so that I never need the desktop.
3. As the owner, I want to play on my iPhone, iPad or Android device with a controller, so that I can play away from home (the iPhone and iPad at 1.0 since the owner's rulings of 2026-11-17; Android 1.x).
4. As the owner, I want one button on any device to put me back in my latest save.
5. As the owner, I want my dump on as few machines as possible.
6. As a contributor, I want one language and one build (`cargo`) for everything of ours, so that the code is easy to change and test on every OS.

## Implementation decisions

- **Workspace** (ADR 0001): `crates/core` (`uncharted_core`: dump and revision checks, prepare, patches, mods, cheats, trophies, render size, recipes, saves, profiles, Steam, artwork, save cards, bundles, hubs, fleet, backup, update), `crates/runtime` (`uncharted_runtime`: the host runtime that replaces `src/`), `crates/cli` (`uncharted-universal`), `app/` (`uncharted-app`, Rust + Slint). `gpu/` stays C++ and CMake, built from `crates/runtime`'s build script, behind the existing `bbgpu.h` C ABI.
- **Moving the runtime** (ADR 0002): strangler order. `crates/runtime` builds as a static library linked with the remaining C; each `runtime_*.c` is replaced by a Rust module exporting the same symbols, its C test becoming a Rust test; the loader (`probe.c`) moves last. A boot smoke test (the game reaches its first frame on a fake image, plus a device check per step on the AMD handheld) gates each step.
- **Launcher** (ADR 0003): all Rust with a Slint UI, as totk-native ADR 0004: view models in plain Rust, `.slint` only draws; gamepad through gilrs on desktop and key events on Android. The Python launcher stays until the Slint app has parity, then goes. The generic modules (vdf, Steam shortcuts, platform folders, hub, bundle, fleet, save card shape) are copied from totk-native (MIT) with credit.
- **Build hubs** (ADR 0004): the Strix Halo tablet (Linux handhelds, Android), the RTX 3090 Ti desktop (Windows), and the Mac (Mac, iPhone, iPad; 1.0 for the Apple apps since the owner's rulings of 2026-11-17); Android from the tablet is 1.x. mDNS discovery, one-time pairing code (SPAKE2), the stream sealed, home network only. The hub prepares the install (boot image, linked modules, patches) and the GPU-independent shader translations, and the player's prepared game data, which it copies to the player's own devices over the home network and never puts in a bundle; a driver pipeline cache ships only between devices with the same GPU and driver.
- **Android** (ADR 0005): keep the approved FEXCore/Turnip route. Issues #207-#210 split out selected build orchestration, a synthetic FEX check, a later guest ABI bridge, and a standalone driver bootstrap. revvv991/uncharted-android is GPL-2.0-or-later and supplies selected build/bridge references; it is not a whole-tree import. zenithblue FEX bridge files are individually marked MIT, while transitive local headers can be GPL-2.0-or-later. bylaw’s libadrenotools source is BSD-2-Clause. #210 requires explicit driver selection, verification of the driver actually loaded, and fail-closed handling; no silent fallback to unvalidated stock Adreno, which the direct port reports hangs in this game. Our Rust runtime still cross-builds for `aarch64-linux-android`. By owner ruling 2026-11-23, Android ships as three separate per-game thin APKs (Uncharted 1, Uncharted 2, Uncharted 3) with no bundled game assets; on boot each APK prompts *"Would you like to download the rest of the game files?"* and pulls its game files from Dropbox through save-relay's Dropbox app (`iannitram/save-relay#305`) with resumable downloads surviving battery death or force-close. Android is 1.x (2026-11-12 scope ruling): it does not block 1.0.
- **Apple** (ADR 0006): retain the approved recompiled-library/Metal route, gated by #211 source/synthetic feasibility and a file-level license/dependency map; #212 adds synthetic no-JIT CPU coverage only after that gate. No game dump or executable analysis is authorized by these research issues. The Bloodborne peers are feasibility evidence, not a proven Uncharted port: the recompiler has title-specific assumptions, iOS disables JIT, and the runtime tree contains a GPL-3.0 network component that must not be imported. If the gate passes, vendored platform code may stay in its language behind the existing C ABI; our core/runtime remain Rust. The Mac/iOS app commitments remain as planned, with the iPhone/iPad release split into three separate per-game thin unsigned `.ipa` apps (Uncharted 1, Uncharted 2, Uncharted 3; no bundled game assets) installed from Dropbox with SideStore and my free Apple ID (M15, owner rulings 2026-11-18 and 2026-11-23); on boot each iOS app prompts *"Would you like to download the rest of the game files?"* and pulls its game files from Dropbox through save-relay's Dropbox app (`iannitram/save-relay#305`) with resumable downloads surviving battery death or force-close. Apple was 1.x by the 2026-11-12 scope ruling. Since the owner's rulings of 2026-11-17, the Mac and iPhone/iPad apps, their controllers and their save-relay are 1.0 (M16, M18), so the Apple pieces they need block 1.0.
- **Saves:** [iannitram/save-relay](https://github.com/iannitram/save-relay) is the shared sync dependency for all five platforms. Reference it now and attach its integration when the relevant platform support and interface are ready; readiness belongs to that repo. A manifest for the collection (#163) names each game's savedata folder per device; the same savedata layout on every device lets a save move unchanged. On iOS/iPadOS (1.0) and Android (1.x), save-relay's Dropbox app also carries the resumable per-game game-file downloads on first boot (`iannitram/save-relay#305`). This records the intended integration, not current cross-platform sync availability.
- **Windows:** the existing CLANG64 toolchain for the C++ parts; Rust target chosen at the issue (`x86_64-pc-windows-gnullvm` to match, or MSVC).

## Testing decisions

- Core logic (dump and revision checks, prepare steps, patches, mods, recipes, saves, Steam files) is tested with fake dumps in `cargo test` on Linux, Windows and macOS. The 34 Python test files are the expected results for their Rust ports.
- Each runtime module's Rust tests replace its C test; the boot smoke test runs in CI on Linux.
- Launcher pages are tested through their view models (button presses in, page state out), and once headless through Slint's testing backend.
- Hub pairing, transfer and the fleet view are tested with a fake hub on loopback.
- Everything that runs the game on hardware is a device check (`needs-owner-device`).
